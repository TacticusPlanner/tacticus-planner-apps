- [x] 1.1 Add `expectedGold: z.number().nullable().optional()` to `farmLocationSchema` (`packages/game-catalog/src/schemas/shared.ts`) — `.optional()` is required, not cosmetic: a `looseObject` still hard-fails `safeParse` when a _declared_ key is entirely missing from the payload, so without it a client on this schema deployed even momentarily ahead of (or out of sync with) the companion API's field breaks catalog loading for every dataset, not just the gold tie-break. - [x] 1.2 Add `expectedGold?: number | null` to `FarmLocation` (`apps/web/src/fsd/shared/lib/battle.domain.ts`) — **deviates from the plan's "normalize at the mapping boundary"**: `mapUpgradeStorageToDomain` turned out to be one of _several_ places that pass a catalog storage model's `farmLocations`/`shardLocations` straight through as `FarmLocation[]` with no per-location reshaping step (e.g. `daily-raids-calc.ts`'s `shardLocations: character.shardLocations`), so there's no single mapping boundary to normalize at. Made `expectedGold` optional (matching the zod-inferred shape exactly) instead, so every existing passthrough keeps type-checking with zero new code, and the one consumer that cares about the null/absent distinction (`selectFarmNodes`'s tie-break) treats both identically via `?? Number.NEGATIVE_INFINITY`. Verified by `pnpm typecheck` passing across the whole app
