This section is dropped, not merely blocked. Empirically, `pnpm lint:fsd` (steiger's `fsd/forbidden-imports` rule) forbids `pages/projects` importing anything from `pages/goals`'s public API — same-layer page-to-page imports are disallowed even through `index.ts`. `ProjectsPage` depends on deep `pages/goals` internals (`GoalsList`, `GoalDetailSheet`, and ~20-30 supporting model/hook files for attainment, estimates, blockers, insights) that Overview also uses. Moving it out would require first extracting all of that shared infrastructure into a new `widgets/` layer — a large, high-risk refactor of business-critical calculation code not scoped in proposal.md/design.md's Impact list. Decision (relayed from the change owner): keep Projects inside `pages/goals` — revert design.md's Decision 6 entirely rather than pursue the `widgets/` extraction. `design.md` and `proposal.md` have been updated accordingly. All of sections 2-8 below are implemented with `ProjectsPage` at its existing location, `pages/goals/ui/projects/projects-page.tsx`.

**Design decision made during implementation, not fully specified in `design.md`:** `ProjectDetailPage`'s manual reorder (up/down) buttons are now gated on `tab === "toReach" && sort === "updated" && group === "none" && goalType === "all"` (the page's original, only-ever-supported state) rather than always-on. Reordering swaps positions within the currently _displayed_ row order and submits that as the new priority; once `GoalFilters` lets the display order diverge from priority order (any non-default sort/group/type), reordering would silently submit a swap that doesn't match what the user visually did. This wasn't anticipated in `design.md`'s Decision 12 (which only said the detail route "gets the same Type/Sort/Group filters Overview has," without addressing the reorder interaction Overview never had to consider). Flagging for review rather than treating it as settled - an alternative would be hiding the reorder feature's entry point differently, or disabling just the Sort control while `toReach` reorder is active, instead of hiding reorder when Sort changes.
