## Why

The desktop sidebar currently exposes the full navigation tree — top-level sections _and_ every section's child pages (Lookup > Character/MoW/NPC, Progress > Onslaught/Campaigns/Campaign Events/XP Income, etc.) via expandable sub-items. Every one of those sections (Lookup, Goals, Progress, Guild, Dailies) already renders its own routed tab bar for exactly those same child pages at the top of the page content. The result is the same Level-2 destinations listed twice, in two different controls, and the sidebar's expand/collapse state adds UI complexity (chevrons, active-branch expansion, layout shift) that duplicates what the page-level tabs already do more legibly. The mobile menu drawer has the same full-tree structure, but — per explicit product direction — that duplication is being left as-is on mobile; only the desktop sidebar is being flattened.

## What Changes

- **BREAKING (UI behavior)**: Remove child-item rendering from the desktop sidebar (`AppSidebar`/`NavMenuItem`'s `SidebarMenuSub`) — the sidebar becomes a flat list of top-level sections only (Home, Lookup, Goals, Dailies, Progress, Guild), with no chevrons or expand state. A section is highlighted active whenever the current route falls under it, matching today's behavior.
- The mobile bottom-nav's "Menu" drawer keeps its current behavior unchanged: it continues to list every top-level section with its child pages nested beneath it as direct links, exactly as today. This change does not touch the drawer's structure.
- Add "remember last visited child page" behavior scoped to the desktop sidebar only: clicking a multi-child section's entry point in the sidebar navigates to the last child route the user visited within that section during the session, falling back to that section's existing default child (e.g. Lookup > Character) the first time the section is entered in that session. This does not apply on mobile — the drawer already shows every child page as its own direct link, so there is no hidden default to resolve there. Single-child sections (Guild) and Level-1-only routes (Dailies, whose own tab bar is its top-level content) are unaffected on desktop too — they keep navigating to their existing default route.
- **BREAKING (UI restructure)**: Move every section's page-level routed tab bar (Lookup, Goals, Progress, Guild, Dailies) out of the page content and into the shared app-shell header itself, directly beneath the title/description, replacing each page's own ad hoc `Tabs`/`TabsList`/`TabsTrigger` block (`goals-layout.tsx`, `progress-layout.tsx`, `lookup-page.tsx`, `guild-registered-view.tsx`, `dailies-layout.tsx`) with one shared header-tabs component driven by `nav-items.ts`'s `children`. This applies on both desktop and mobile. `Dailies > Raids`' own nested Today/Raids Plan sub-tabs are a third level and are unaffected — they stay in `raids-layout.tsx`'s own page content, unchanged.
- Dailies gains `children` in `nav-items.ts` (Raids, Shops, Onslaught, Salvage Run, Arena, Guild Raids, in that order) so its six primary tabs participate in the same header-tabs/description/search/last-visited-child machinery as every other multi-child section, instead of being a special case. Its labels/descriptions are added to `common.json` alongside the other sections' (duplicating, not replacing, the existing `dailies` namespace's own `tabs.*` strings — see design.md's Decisions for why).
- Add a short one-line description for every navigation item — top-level sections and their child pages, including Dailies' six — and surface it in four places: the mobile menu drawer (beneath each item's label, including nested children), the desktop navigation search dialog (beneath each result's label, including children), the mobile bottom navigation bar's menu (same), and the shared page header (under the title, on both desktop and mobile, now directly above the moved tab row). The desktop sidebar and the mobile bottom navigation bar's primary icons are unaffected and stay icon+label only. Desktop and mobile navigation search matching extends to also match against an item's description text, not just its label.
- The header description swaps with navigation on both platforms: on a section's own top-level page (or a section with no matching child, e.g. Home) it shows that section's own description; on a child page (e.g. `/lookup/mow`, `/dailies/raids`) it shows that child's own description instead. This replaces the per-page title+description blocks several pages already rendered on their own (Goals > Projects, Goals > Insights, all four Progress tabs, Dailies > Raids) — those are deleted from page content since the header now shows the same information; their real existing copy is reused as each item's `descriptionKey` text instead of being invented fresh. Pages that had no such block (Lookup's three tabs, Guild > Members, Dailies' five placeholder tabs) are unaffected beyond gaining the header treatment.
- **BREAKING (UI restructure, desktop only, revision)**: On mobile, the header title also swaps to the active child's own label, same as the description, exactly as shipped. On desktop, the header title stays pinned to the top-level section's own label at all times (e.g. "Lookup", never "Machines of War") — it no longer swaps to the active child. Instead, the section's child pages sit inline in the same row as that title: as a row of plain nav-style links (not the boxed `Tabs` component) for a section with 6 or fewer children — today, every section — or, for a section with more than 6, a breadcrumb dropdown reading "Section › Active child" (e.g. "Dailies › Raids") that opens a menu of every child page. This replaces the desktop header's previous stacked title-row-then-tab-row layout with one combined row; `pageDescription` is unaffected and keeps rendering as its own row beneath, still swapping to the active child's description exactly as before.
- **Fix (incidental)**: horizontal tab rows styled with `overflow-x-auto` alone (Dailies > Raids' own nested Today/Plan sub-tabs, and mobile's header tab row) showed a spurious vertical scrollbar due to a CSS overflow-computation quirk. Fixed by also setting `overflow-y-hidden`.
- Keep the desktop navigation search dialog and the mobile drawer's search field indexing every route, including section children — full-tree search discoverability is unaffected by this change.
- Add a desktop keyboard shortcut, Ctrl+K (Cmd+K on macOS), that opens the navigation search dialog from anywhere in the app, or closes it if already open — mirroring the existing Ctrl/Cmd+B sidebar-toggle shortcut already implemented in `packages/ui/src/components/sidebar.tsx`. Show a platform-appropriate shortcut hint ("⌘K"/"Ctrl+K") next to the sidebar's Search button so it's discoverable. Desktop only — there is no mobile equivalent.
- Add two more desktop keyboard shortcuts, same pattern: Ctrl+G (Cmd+G on macOS) triggers Create Goal — the same action as clicking the sidebar's Create Goal button — from anywhere in the app; Ctrl+Shift+S (Cmd+Shift+S on macOS) triggers Sync with Tacticus — the same action as clicking the sidebar's Sync button, inheriting that button's existing disabled-while-a-sync-is-in-flight guard. Both show a shortcut hint next to their sidebar button, both desktop only.
- The shared nav/shell Joyride tutorial (`general.tutorial.tsx`) already targets only top-level `desktop-nav-*`/`mobile-nav-*` items, not sidebar/drawer child-items, so it needs no retargeting — verify this holds after the sidebar flattening.

## Capabilities

### New Capabilities

- `app-navigation`: Behavior of the app-wide navigation shell — desktop sidebar, mobile bottom nav and menu drawer, navigation search, item descriptions, and how the desktop sidebar resolves a section entry to a starting child route.

### Modified Capabilities

(none — `app-navigation` did not previously exist as a documented capability; the per-page tab bars it references, e.g. Dailies' navigation, keep their existing documented behavior unchanged)

- `apps/web/src/fsd/app/layout/mobile-layout.tsx` and `mobile-drawer-sub-item.tsx` — unchanged structurally (children keep nesting); gain description rendering under each label (parent and child) in both the drawer and the page header.
- `apps/web/src/fsd/app/layout/nav-items.ts` — `NavItem`/`NavSubItem` gain a description key field; add desktop-only entry-path resolution (default vs. last-visited) alongside the existing `path`/`children`; Dailies gains a `children` array (Raids, Shops, Onslaught, Salvage Run, Arena, Guild Raids).
- `apps/web/src/fsd/app/layout/desktop-navigation-dialog.tsx` — render each result's description beneath its label.
- New shared header-tabs component (e.g. `apps/web/src/fsd/app/layout/section-tabs.tsx`) rendering a section's `children` as a routed tab row, reused by both `desktop-layout.tsx`'s and `mobile-layout.tsx`'s headers — replacing each page's own tab implementation.

- i18n: add a short description string for every top-level and child nav item (including Dailies' six) to every supported locale (`de`, `en`, `es`, `fr`); reuse each already-existing page's real title/description copy as the source text wherever one already existed (Goals > Projects/Insights, all four Progress tabs, Dailies > Raids), rather than inventing new copy for those.
