## Decisions

1. **Bulk add sends one request per project, in sequence.** Each uses today's single-destination path, including its `membershipStale` retry. They run one after another, so the toasts and the cache updates stay simple. The result is one toast: "Added 3 goals to Chaos Core and Team Lavi", or "Added to Chaos Core. Team Lavi failed. Retry" with Retry for the failed ones only.
2. **Add to another project… reuses the membership picker** from the Edit goal dialog in a small dialog (desktop) or sheet (mobile), saving only memberships. It is placed right after Edit in every goal row menu, scoped or not. Existing scenarios that enumerate row menus predate the move items and describe relative order; they are unchanged.
3. **Portraits come from data already joined.** The card already joins `goalIds` with the goals list for its unit count. The first 4 distinct units, by the global priority of their highest goal, render as overlapping 24 px round portraits (20 px in the home widget), with "+N" for the rest. No extra read. Owning slice: `features/project-management/ui/project-unit-portraits.tsx`, which uses `entities/unit` for portraits.
4. **Filter state.** The chips are page-local state on the Projects route, defaulting to All. The value is kept in `?kind=` so it survives reload and back navigation, and resets to All when the chosen kind no longer exists among the listed projects. The kind list derives from the loaded projects.
5. **Desktop and mobile.** Desktop shows the chips in one row above the list. Mobile puts them in a horizontally scrolling row. The bulk picker on mobile is the existing sheet with checkboxes. The Projects tour gets a `kindFilter` step (`[data-testid="projects-kind-filter"]`), skipped when the chips are hidden.
