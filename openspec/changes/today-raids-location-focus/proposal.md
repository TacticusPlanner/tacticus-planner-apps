## Why

Today's raid schedule currently foregrounds _what_ to farm (a large unit or material icon) and buries _where_ to go behind small, abbreviated location chips — but a player opening this page is primarily deciding where to raid next. Separately, the energy indicator next to the page title reflects this app's own budgeted plan rather than the player's real, synced account usage, so it can't tell a player they've already spent more energy today than they planned for. This change re-weights Today and Bonus Raids toward location, gives finished locations and goal types their own clear visual treatment, and adds a real energy-usage indicator sourced from the player's actual synced attempts.

## What Changes

- Today and Bonus Raids cards flip visual precedence: the raid location (campaign icon, full campaign/tier name, and battle/node number) becomes each card's primary element, and the farmed material/resource becomes a secondary caption. When a resource is farmed at more than one location, each location renders as its own full-weight row instead of a small chip. The existing combined-shard-identity row keeps the unit portrait/name as the card's identity, with its location(s) rendered in the same new bigger-row style beneath it. The Raids Plan tab is unchanged — it keeps its current material-primary cards and location chips, since it reuses the same rendering component and this change adds an opt-in variant rather than altering its default.
- A new "Fully Raided" section is added after Bonus Raids, listing locations that have hit their daily attempt cap today (a state Today already computes per-node, just not surfaced as its own group). A location that reaches its cap moves out of its normal resource-card row into this section rather than appearing in both places; if every location for a resource becomes fully raided, that resource's card drops out of the schedule/Bonus Raids for the day and surfaces only here.
- Today's title row gains an energy-usage progress bar showing the percentage of the player's configured daily energy actually spent today, computed from the player's real synced attempt counts across every standing (standard/mirror/elite/eliteMirror) campaign node on the account (not just nodes in this project's plan) — so, unlike the plan's own budgeted energy total, this figure can exceed 100%. Event-campaign attempts are excluded from this total: real synced attempt data doesn't retain which difficulty tier (Standard/Extremis) an event attempt belongs to, so it can't be priced reliably (a known undercount for event-campaign activity specifically, not a bug).
- Each goal's target now shows an icon instead of plain-text-only: Rank goals show the Rank goal-type icon paired with the rank icon (no text); every other goal kind (Ability, Ascension, Unlock, Level, Upgrade) shows its goal-type icon paired with text, matching the icon/text treatment already used by the Create Goal sheet's goal-type picker.

## Capabilities

### Modified Capabilities

- `daily-raids-today`: Today's card layout becomes location-primary instead of material-primary; campaign location presentation changes from a compact short code to the full campaign/tier name plus battle number; a new Fully Raided section is added after Bonus Raids, and a location moves into that section instead of remaining inline once it's fully raided (this also modifies the existing "Today's raid schedule" requirement's per-node fully-raided indicator, replacing the in-place badge with exclusion from the list); a real, account-wide energy-usage indicator is added next to the page title; goal cards show a goal-type icon (goal-type icon + rank icon for Rank, icon+text for every other kind).

## Impact

- Affected code: `apps/web/src/fsd/pages/dailies/ui/raid-schedule.tsx` (`ResourceCard`/`GoalHeader` gain a location-primary rendering path, opt-in via a new prop so `raids-plan-page.tsx`'s usage is unaffected), `today-page.tsx` (new Fully Raided section, energy progress bar), `model/daily-raids.domain.ts` (`DailyRaidLocationViewModel` splits its single `label` into full name/node number/challenge fields; `DailyRaidGoalViewModel` carries the raw goal kind and, for Rank, the raw rank value, instead of only a pre-formatted `targetLabel`), `model/use-daily-raids.ts` (computes the split location fields; reads and joins `live-progress.battleAttempts` — currently fetched but unused beyond `activeCampaignEventId` — against the campaign battle catalog for the real energy-usage figure).
- New shared UI: the existing `goalTypeIcon()`/`GoalTypeBadge` (today page-local to `pages/goals/ui/shared/goal-visuals.tsx`) relocates to `apps/web/src/fsd/entities/goal/` as a proper public API, since Dailies is a separate page and FSD forbids page-to-page imports; the Goals page's own usages are updated to import from the new location. `RankBadge` (`fsd/shared/ui/rank-badge.tsx`) is reused as-is with `showLabel={false}`.
- New data join: a `battleIndex → BattleId` mapping for standing (standard/mirror/elite/eliteMirror) campaigns (battleIndex is the 0-based ordinal position of a node within its `tacticusCampaignId`'s node list, not currently mapped anywhere in this app's `game-catalog`/`shared/lib`) is needed to price each real attempt by its node's `energyCost`; for these campaign types the mapping is a direct `nodeNumber = battleIndex + 1`. Event campaigns are excluded from the join — see `design.md` Decision 4 for why `battleIndex` is ambiguous there in the currently-stored data.
- i18n: new copy (a "Battle {{number}}" label, the Fully Raided section title, the energy-usage progress bar's label) added to `apps/web/public/locales/*/dailies.json` across all locales (en/de/es/fr).
- Joyride: `today.tutorial.tsx` needs new/updated steps for the Fully Raided section and the energy progress bar.
- No backend/API impact — frontend-only, and this is a pre-production V2 submodule, so the internal view-model shape changes above need no compatibility shim.
